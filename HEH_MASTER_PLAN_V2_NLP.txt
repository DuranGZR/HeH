01. ÜRÜN KİMLİĞİ VE PROBLEM TANIMI (PRD)
======================================================================
Ad: HEH | Logotype: heh. | Slogan: 'Heh, tam aradığım.'
Kısa yönlendirme: 'Söyle. Kontrol et. Bul.'
Tür: Ses/yazı destekli, çok kriterli arama bağlantısı oluşturucusu.
HEH bir e-ticaret mağazası, ürün katalogu, fiyat karşılaştırma veya sohbet botu DEĞİLDİR.

Problem:
- Kullanıcı birçok kategori/filtreyi elle açıp eşleştirmek zorunda kalıyor.
- Kullanıcı doğal cümlede olumsuzluk, alt/üst sınır, alternatif marka ve nitelik söyleyebiliyor.
- Standart kelime araması ile kesin filtre arasında boşluk var.

Değer önerisi:
- Tek cümleyle istek toplama.
- Açıkça görülen, tek tek düzenlenebilen kriterler.
- HEH'in güvenilir biçimde uygulayabildiği filtrelerle mağazaya yönlendirme.
- Uygulanamayan kriterleri gizlemeyen şeffaf davranış.
- Widget'tan mümkün olan en kısa erişim; misafir kullanım.

Başarı tanımı:
- Kullanıcı ilk denemede doğru kriterleri görür veya en fazla birkaç dokunuşla düzeltir.
- Filtreli bağlantı, TEST EDİLMİŞ koşulların çoğunu tutarlı uygular.
- Kullanıcı yanıltılmaz: q'daki bir kelime renk/marka filtresi diye sunulmaz.
- Üçüncü taraf marka/Trendyol ile resmî ortaklık izlenimi yaratılmaz.

Birincil persona: Filtreden sıkılan mobil alışveriş kullanıcısı; Türkçe yazı/ses.
İkincil persona: Cihaz ana ekranından hızlı arama başlatmak isteyen tekrar kullanıcı.

P0 kullanıcı öyküleri:
US-01  Misafir uygulamayı açıp mikrofona basmadan ana ekranı görür.
US-02  Mikrofonu seçer; izinler açıklanır; Türkçe transkript görüntülenir/düzenlenir.
US-03  Alternatif olarak yazarak sorgu gönderebilir.
US-04  Kategori, bütçe, marka, beden, renk, hariç tutma koşulları ayrıştırılır.
US-05  Kriterleri siler/değiştirir; sistem yeniden hesaplar.
US-06  Uygulanmış / metne konmuş / uygulanamamış ayrımı görür.
US-07  Trendyol'a güvenli bir HTTPS bağlantısıyla geçer.
US-08  Yerel arama geçmişini inceleyip tekil/toplu silebilir.
US-09  Widget sesli veya yazılı arama ekranını açar; izin olmadan kayıt başlamaz.
US-10  Ses, internet ve yönlendirme hatalarında yazıyla devam edebilir.
US-11  İsteğe bağlı hesap açıp geçmiş senkronizasyonunu seçebilir.
US-12  Hesabını ve sunucu verilerini silebilir; gizlilik metnini görebilir.

V1 DIŞI (bilinçli ertelenenler):
- Affiliate/komisyon entegrasyonu ve Premium üyelik.
- LLM, embeddings, RAG, agent, Qdrant, Rust, Celery, Kafka, microservices.
- Trendyol'dan izinsiz scraping, botla filtre tıklama, otomatik fiyat/stok çekme.
- Gerçek ürünleri uygulama içinde listeleme veya 'tam eşleşme' yüzdeleri.
- Çoklu pazaryeri, fiyat alarmı, sanal deneme, sepet/satın alma otomasyonu.
- Hesap zorunluluğu, sosyal akış, bildirim spam'i, gereksiz onboarding.

Ürün anti-hedefleri:
- Çok filtre yazılmış diye her kriteri uygulanmış göstermemek.
- Kullanıcıyı misafir kullanım yerine kayıt duvarına zorlamamak.
- Ana ekrana reklam, ürün kartı, alt sekme veya yapay zekâ süsleri doldurmamak.

02. BAŞLANGIÇ KABULLERİ, KESİN KARARLAR VE AÇIK RİSKLER
======================================================================
KULLANICI TARAFINDAN KARARLAŞTIRILANLAR:
- iOS + Android birlikte.
- React Native + TypeScript.
- Tek geliştirici, günde ortalama 5 saat.
- App Store + Google Play'e gönderilebilir kalite hedefi.
- FastAPI + PostgreSQL en baştan kurulacak.
- Affiliate V1 için yok; buna ait boş kod/ekran eklemek gerekmiyor.
- HEH'in mevcut siyah-beyaz, Apple ilhamlı minimalist dilini koru.
- Kullanıcının kontrolündeki mikrofona dayalı deneyim; widget desteği.
- LLM API'siz kapsamlı Türkçe NLP: sayı/fiyat/birim ve AND/OR/NOT kapsam ağacı her zaman
  deterministik kurallarda kilitlidir; önce W4-W6'da M0 baseline ile uçtan uca mobil
  Text+STT dikey dilimi çalıştırılır, ardından W7-W11'de DistilBERTurk açık uçlu
  varlık/kategori aday çıkarımı denenir ve geçerse PyTorch'suz ONNX Runtime (INT8/FP16) ile sunulur.
- Modelin varlığına değil test setinde kazandırdığı kaliteye ve gecikmeye göre deploy kararı.
- Ağır ML R&D ve eğitim 'projenin ilk gününde' değil, W4-W6 çalışan dikey dilim
  ve gerçek cihaz STT gözlemlerinden sonra W7-W11 gate'leriyle yapılır.

MİMARİ YÖNLENDİRME (geliştirici kararı):
- NLP Query Understanding backend üzerinde ayrı sürümlü bir domain + adapter katmanıdır.
- Ana parser, kriter eşleme ve URL inşası sunucu tarafında tek kaynak (FastAPI).
  Gerekçe: URL eşleme verisi ve parser kuralı mağaza uygulama güncellemesi olmadan değiştirilebilir.
- Tek-İstekli (1-RTT) Arama Kontratı: POST /api/v1/search/parse tek seferde hem SearchIntent
  AST'sini hem de ilk LinkResolution (URL + applied/query_only/unsupported) önizlemesini döndürür;
  POST /api/v1/search/resolve yalnız kullanıcı UI'da kriter sildiğinde/düzenlediğinde NLP
  koşturmadan yeni URL hesaplamak için çağrılır.
- Zero-DB Hot Path: /search/parse, /search/resolve ve /search/capabilities uçları versiyonlu
  ve SHA-doğrulanmış bellek-içi salt-okunur (in-memory immutable) mapping snapshot'ını okur;
  hot path'te sıfır PostgreSQL sorgusu vardır. DB kapansa bile misafir arama %100 ayakta kalır.
- Dar ve Derin Trendyol Kapsamı + TrendyolRouteStrategy: V1'de 5-8 vitrin kategoride
  (Mont/Üst Giyim, Ayakkabı, Kulaklık, Laptop, Akıllı Telefon vb.) tam kanıtlı FILTER_VERIFIED
  desteği sağlanır; uzun kuyruk kategorilerde doğrulanmış fiyat aralığı (prc) + akıllı q
  metnine düşülür. URLBuilder hem SEO slug + -x- birleşik facet path'ini hem /sr query
  stratejisini soyutlar, yalnız kanıtlanmış rotayı kullanır.
- Mobilde gösterim mantığı, metin girişi, STT, yerel geçmiş önbelleği bulunur.
- Sunucu kapalıysa sihirli bir filtreleme vaadi sunulmaz; kullanıcı mevcut geçmişini
  görebilir ve isteğini kopyalayabilir. İleri sürümde 'temel arama' fallback'i değerlendirilebilir.
- Backend monolit + açık modül sınırları; ilk sürümde mikroservis yok.
- Hesap opsiyonel: öncelik misafir akış; hesap yeteneği beta öncesi ayrı iş paketi.
- Arama metni sunucuda kalıcı saklanmaz; hesaplı geçmiş açık rızayla ve yönetilebilir biçimde saklanır.
- Sabit filtre sözlüğü 'id tahmini' değil; doğrulama kanıtına bağlı sürümlü kayıt.

BAĞIMLILIKLAR / GATE:
GATE-0 (W1 / ilk 5 iş günü): Trendyol'da en az 3 vitrin kategori için hem /sr?... hem de
  SEO slug + -x- birleşik facet path davranışı elle test edilmeli. Başarısızlık 'hedefin
  imkânsız' olduğu anlamına gelmez; ama mağaza filtrelerini yüzde yüz uygulama iddiası durdurulur.
GATE-M0 (W4): Deterministik Türkçe kural motoru (sayı/fiyat + AND/OR/NOT AST) çekirdek 200 golden senaryoda geçer.
GATE-VSLICE-TEXT (W5): Uçtan uca mobil metin arama -> tek-istekli önizleme -> düzenleme -> Trendyol akışı iki platformda çalışır.
GATE-VSLICE-VOICE (W6): Gerçek iOS + Android cihazda STT -> M0 -> düzenlenebilir kriter akışı çalışır; gerçek ASR hata günlüğü toplanır.
GATE-NLP-A (W7): Gerçek STT gözlemleriyle zenginleştirilmiş ontology, AST ve annotation policy onaylanır.
GATE-NLP-B (W8): Etiketli dataset (gerçek ASR dilimi dahil), group-split leakage denetimi ve dondurulmuş M0 tam benchmark yayımlanır.
GATE-NLP-C (W9): Daraltılmış rollü DistilBERTurk (M2) ve lineer M1 deneyleri değerlendirilir.
GATE-NLP-D (W10): Kural-öncelikli hibrit birleştirme, kalibrasyon, ONNX (INT8/FP16) eşdeğerlik/gecikme testi ve M0/M1/M2/M3 ablation onaylanır.
GATE-NLP-PROD (W11): PyTorch-free ONNX serving / shadow / NLP_MODE=rules fallback şartlı onaylanır.
GATE-1: Query understanding güvenli golden kritikleri geçmeden otomatik filtre iddiası yok.
GATE-2: Widget ve STT gerçek iOS + Android cihazda çalışmalı.
GATE-3: Gizlilik, hesap silme, mağaza inceleme ve güvenlik kontrol listeleri geçilmeli.

Belirsizlik halinde ürün kararı:
A) Gerçek filtre parametresi doğrulanmış -> URL filtresine aktar.
B) Sadece arama kelimesi ile ilişkilendirilebilir -> 'Metinle arandı' de.
C) Negatif/belirsiz şart veya doğrulanamayan filtre -> 'Uygulanamadı' de,
   kullanıcıya düzenleme/tekil seçim teklif et. Sessizce yok sayma.
D) Desteklenmeyen kritik zorunlu şartlar baskınsa CTA'yı 'Kısmi aramayı aç' olarak etiketle.

03. GÜNCEL TEKNOLOJİ YIĞINI VE SÜRÜM POLİTİKASI
======================================================================
V1 ANA YIĞINI (23.11.2026 itibarıyla):
- Mobil: React Native 0.88 + Expo SDK 58 (uyumluluk: resmi Expo SDK matrisi), TypeScript strict.
- Yönlendirme: Expo Router; tek kök arama akışı, yardımcı ekranlarda modal/bottom sheet.
- Derleme: EAS Build + development builds (widget/STT için yalnız Expo Go'ya dayanma).
- Widget: SDK 58 'expo-widgets' (iOS/Android); ilk hafta iki platform için POC.
  Gerekirse platforma özgü SwiftUI/WidgetKit ve Kotlin/Glance fallback adapter.
- Konuşma tanıma: iOS SFSpeechRecognizer / Android SpeechRecognizer'u saran,
  development build uyumlu ve bakımı doğrulanan bir modül. Aday: expo-speech-recognition;
  kütüphane seçimi ve izin işleyişi gerçek cihaz POC'den sonra ADR ile sabitlenir.
- İstemci veri/istek: TanStack Query + fetch tabanlı typed API istemcisi.
- Hafif UI durumları: React Context/useReducer; gereksiz global state kütüphanesi yok.
- Cihaz verisi: expo-sqlite; kimlik tokenı/kimlik bilgisi: expo-secure-store.
- Paket yönetimi: pnpm workspace, pnpm-lock.yaml; Node LTS sürümü .node-version ile sabit.
- UI testleri: Jest/React Native Testing Library (uyumlu sürüm) + Maestro cihaz E2E.
- API: Python 3.12, FastAPI, Pydantic v2, SQLAlchemy 2.x, Alembic, pydantic-settings.
- NLP rules/runtime: Python regex, Unicode/NFC, Turkish-aware normalization,
  Decimal/typed AST, pure rule grammar (sayı/fiyat/birim ve AND/OR/NOT kapsamı
  her modda deterministik kurallarda kalır) ve kategorik ontology.
- NLP R&D (W9-W10, yalnız offline ml/ ortamı): PyTorch, Transformers, Datasets,
  Evaluate/seqeval, scikit-learn, optimum/onnx/onnxruntime quantization araçları;
  gerektiğinde Sentence Transformers. Üretim API konteynerine PyTorch/Transformers eklenmez.
- NLP weights: registry/sha/lisans + ayrı artifact store; Git reposuna checkpoint koyma.
- NLP serving (W11): Kapıyı geçen DistilBERTurk adayının ONNX Runtime (onnxruntime CPU,
  INT8/FP16) ile tek servis içinde hafif çıkarımı (düşük RAM, tek sorgu CPU hedefi ~30-50 ms);
  yük gerektirirse ayrı inference container ADR, varsayılan microservice YOK.
- Python bağımlılıkları: uv + pyproject.toml + uv.lock; Ruff + pytest + pytest-asyncio/httpx.
- Veritabanı: PostgreSQL 17+; migration'lar Alembic; yerelde Docker Compose.
- Kimlik: Yönetilen OIDC/email OTP sağlayıcısı tercih edilir (öneri: Supabase Auth).
  Supabase Auth'ın JWT/JWKS yapısı ve kullanım koşulları entegre edilmeden sabitlenmez.
- Production backend: Tek FastAPI servis; TLS arkasında, yönetilen PostgreSQL,
  otomatik yedekleme ve ayrı staging; sağlayıcı seçimi ADR ile kayıt altına alınır.
- Rate limit: Girişe açık API için edge/WAF limiti; çoklu instance gerekiyorsa Redis
  destekli dağıtık sayaç. Redis daha ilk gün zorunlu servis değildir.
- İzleme: Sentry (crash/backend hata, PII scrubbing); yapılandırılmış JSON log.
- Ürün analitiği: Opt-in / gizlilik sınıflandırmasına uygun asgari eventler; ham sorgu yok.
- CI: GitHub Actions (ilk gün); CD: EAS Workflows / backend deploy otomasyonu kademeli.
- Secret yönetimi: GitHub environment secrets / hosting secret store / EAS env vars.

SÜRÜM POLİTİKASI:

06. UÇTAN UCA DURUM MAKİNESİ VE SİSTEM AKIŞI
======================================================================
User opens App/Widget -> Home -> Text/Voice -> Normalize -> POST /search/parse
-> (SearchIntent AST + Initial LinkResolution in 1 RTT, Zero-DB) -> CriteriaReview
-> [if user edits chip/price: POST /search/resolve -> Updated LinkResolution]
-> user confirms -> OS opens allowlisted HTTPS Trendyol URL.

Durumlar:
IDLE, REQUESTING_PERMISSION, LISTENING, EDITING_QUERY, PARSING, REVIEWING,
RESOLVING, READY_TO_OPEN, OPENING_EXTERNAL, ERROR.

Geçiş kuralları:
- Tek bir request_id ile istek takip edilir; kullanıcı yeni girdi girerse eski sonucu iptal et.
- İlk sorguda mobil istemci /search/parse ardından ikinci bir /search/resolve isteği atmaz;
  /search/resolve yalnız kullanıcı CriteriaReview ekranında kriter düzenlediğinde/sildiğinde
  NLP koşturmadan güncellenmiş AST üzerinden yeni URL hesaplamak için çağrılır.
- Out-of-order yanıt en güncel sorguyu ezemez; AbortController/cancel token.
- Aynı arama butonuna çift dokunma iki ayrı intent başlatmaz.
- Başarılı parse'ı hemen otomatik Trendyol'a gönderme: kullanıcı filtreleri görsün.
- Dış tarayıcı/Trendyol dönüşü uygulama mevcut review durumunu korusun.
- Widget 'voice' girişinde direkt kayda başlamadan önce izin + foreground koşulu doğrula.
- Gereksiz ağ tekrarlarından kaçın; fakat filtre haritası sürüm değişirse eski linki kullanma.

======================================================================
07. DOMAIN MODEL, PARSER VE KRİTER SEMANTİĞİ
======================================================================
Parser hedefi: Serbest Türkçe metni kontrol edilebilir, test edilebilir yapılara dönüştürmek.

Temel alanlar:
- category (taxonomy_id, normalized_label, parent_category)
- brand (string/id, OR/NOT)
- color, size, gender, material, style, feature
- price (min/max, inclusive, currency TRY)
- sorting (relevance, price_asc, price_desc, newest — yalnız doğrulanmış)
- meta (source: voice|text, parser_version, dictionary_version, warnings)

Önerilen yapı (kısa örnek):
{
  "query": "3 bin altı siyah mont Nike olmasın M beden",
  "locale": "tr-TR",
  "criteria": [
    {"field":"category","op":"eq","value":"mont","required":true},
    {"field":"price","op":"lte","value":3000,"currency":"TRY","required":true},
    {"field":"color","op":"eq","value":"siyah","required":true},
    {"field":"brand","op":"not_in","value":["Nike"],"required":true},
    {"field":"size","op":"eq","value":"M","required":true}
  ],
  "parser_version":"1.0.0",
  "warnings":[]
}

Sıralı işlem hattı:
1) Girdi doğrulama: UTF-8, 1..500 karakter, kontrol karakterleri, çok uzun/düzensiz input.
2) Normalizasyon: Unicode NFC, Türkçe locale, eşdeğer boşluklar, 3 bin / 3.000 / 3000.
3) Tokenization + çok sözcüklü kalıplar: 'kulak üstü', 'su geçirmez', 'en az'.
4) Parasal ifade çıkarımı: '2500-3500', 'en fazla 3 bin', '3 binden ucuz'.
5) Kategori tahmini: belirlenmiş Türkçe sözlük/taxonomy; eşsesli ifade çakışması.
6) Varlık çıkarımı: marka/renk/beden/malzeme; kategori bazlı etiket sözlükleri.
7) Mantık bağlama: AND, OR, NOT, alt/üst, '-den küçük', 'hariç', 'olmasın'.
8) Çelişki tespiti: min>max; 'siyah' ve 'siyah olmasın'; iki ayrı beden şartı.
9) Normalleştirilmiş kanonik kriter listesi, alternatif ve uyarı üretimi.
10) Doğrulanmış mağaza eşleme motoruna devret; parser URL kimliği üretmez.

ZORLUKLAR / TEST ET:
- 'Nike veya Adidas' => OR, iki markayı AND yapma.
- 'Nike olmasın' => NOT; hiçbir zaman Nike pozitif filtresi açma.
- '3 bini geçmesin ama 1500 altı da olmasın' => [1500,3000].
- 'kırmızı değil bordo' => bordo isteniyor; kırmızı dışlaması her durumda garantili değil.
- 'iPhone 13' ifadesindeki 13 beden veya fiyat değil model numarasıdır.
- '40 saat pil ömrü' içindeki 40 fiyat değil ölçü.
- '15,6 inç' virgüllü ondalık; '1.5 kg' kilo/ürün ağırlığı.
- 'L beden' L litre değil; kategori bağlamını kullan.
- '4500'e kadar' sayı ayrıştırmada ek işaretleri.
- '20-30 bin' => 20000..30000; kısaltma bağlamı.
- Transkript hata olasılıkları: 'JBL'->'cey bi el', 'M'->'em'.

Golden dataset:
- W4 başlangıç M0 çekirdek seed ~200 örnek; W6 gerçek cihaz STT hata gözlemleri;
  W7-W10 anotasyon/kalite kapasitesine göre 400-1200 elle incelenen ve eğitim
  varyasyonuyla 1500-3000 hedef dataset.
- Golden test seti, train/dev/test grup ayrımı ve anotasyon kalitesi ile yönetilir.
- Başlangıç en az 200 elle etiketli anonim/fabrike sorgu; veri kategorilere dengeli dağıtılır.
- Giyim, elektronik, ev, kozmetik, negatif ve OR sınır durumları.
- Dosya: tests/golden/queries.v1.jsonl; beklenen normalized criteria ve warnings.
- Parser sürümü değiştiğinde otomatik regresyon. Yeni hata -> önce test, sonra kural.
- Hedef metrikler (başlangıç gate; kanıtlanmış değildir):
    kritik fiyat sınırı F1 >= 0.98; zorunlu negatiflik doğru yorum >= 0.99;
    genel field exact-match >= 0.90; unsupported durumunun dürüst raporu %100.
- Bu eşikler başarılmazsa kullanıcıya otomatik 'kesin arama' diye çıkma.

07A. NLP ÜRÜN SINIRI, BİLİMSEL AMAÇ VE AŞAMALI TASARIM (YENİ)
======================================================================
TEMEL KARAR: NLP'nin ağır ML R&D fazı PROJENİN 1. GÜNÜNDE KODLANMAZ. W1-W3 ürün riski,
domain kontratı, filtrelerin gerçekten uygulanabildiğinin kanıtı ve Zero-DB iskeleti kurulur;
W4'te deterministik M0 baseline, W5-W6'da ise gerçek iOS/Android cihazlarda uçtan uca
metin + ses (STT) dikey dilimi ayağa kaldırılır. W7-W11 dönemi bu canlı ürün ve gerçek STT
gözlemleri üzerinde yürütülen ciddi HEH NLP Engine araştırma ve MLOps sprintidir.
NLP baştan sona mimari sınır olarak tasarlanır; ağır ML geliştirme dikey dilim çalıştıktan sonra yapılır.

HEH, 'chatbot' değil bir TÜRKÇE COMMERCE QUERY UNDERSTANDING (CQU) motorudur.
NLP'nin görevi kullanıcının söylediklerini bozmayarak CanonicalSearchIntent üretmektir.
NLP'nin görevi Trendyol ürünlerini listelemek, stok/fiyat doğrulamak veya
Trendyol filtre parametrelerini uydurmak DEĞİLDİR.

BAŞARI İÇİN AYRILMIŞ DÖRT SORU:
1. Kullanıcının söylediğini doğru anladık mı? -> NLP evaluation.
2. Kullanıcının açıkça söylemediği varsayımları uydurduk mu? -> Hallucinated constraint rate.
3. Anlaşılan kriter Trendyol'da doğrulanmış filtreye dönüşebildi mi? -> URL mapping evaluation.
4. Gerçek kullanıcı doğru ürüne daha hızlı ulaştı mı? -> Ürün KPI / kullanıcı testi.
Bu dört metriği tek 'AI accuracy' rakamına ASLA birleştirme.

BİRLEŞİK HİBRİT MİMARİ (KESİN GÖREV DAĞILIMI):
Raw input / STT final transcript
  -> Input sanitizer + Unicode normalization
  -> Language/Turkish-aware number & unit parser (HER ZAMAN DETERMINISTIK KURAL)
  -> Domain vocabulary + category router
  -> High-precision span matcher / regular-expression rules (M0 baseline)
  -> [ML flag enabled ise] DistilBERTurk ONNX (INT8/FP16) açık uçlu varlık/kategori/OOD çıkarımı
     (yalnız sözlüğün kaçırdığı aday span ve kategori önerir; sayı/fiyat veya NOT kutbu değiştiremez)
  -> [gerekiyorsa] semantic attribute candidate retrieval
  -> Constraint graph builder (AND/OR/NOT/LOWER/UPPER/PREFERENCE — HER ZAMAN KURAL KİLİTLİ)
  -> Conflict/ambiguity resolver + provenance tracker
  -> Per-slot confidence/calibration + abstain policy
  -> Versioned CanonicalSearchIntent (JSON Schema / Pydantic)
  -> In-memory immutable Provider mapping adapter -> ilk LinkResolution (1-RTT parse yanıtında döner)
  -> Editable human review (yalnız kullanıcı chip düzenlerse /search/resolve)
  -> Applied/Query-only/Unsupported classification
  -> External search with explicit user action.

NLP İÇİN KESİN EN AZ DESTEKLENECEK İŞLEVLER:

B) Named slots: brand, color, material, size, model, product_type, price,

C) Numeric ranges: <, <=, >, >=, [a,b], 'x bin', 'x civarı' (yaklaşık).

L) Unit context: GB, kg, ml, cm, inç, Pa, dB, saat, W, Hz, mAh.
M) Text alias: 'kulaküstü' / 'kulak üstü'; 'gri' / 'füme'.
N) Brand/model collision: 'Apple Watch 9', 'iPhone 13', 'M2', 'S24'.
O) Complex combinations: (Sony OR JBL) AND ANC AND price<=6000 AND NOT white.

======================================================================
07B. KANONİK QUERY LANGUAGE, AST VE VERİ SÖZLEŞMESİ (YENİ)
======================================================================
HATA KAYNAĞI: 'criteria: [{field, operator, value}]' basit sorgulara yeterlidir,
AMA iç içe grup, OR/NOT kapsamı, tercih derecesi ve çelişki yönetimi için YETERSİZDİR.
HEH, AST (Abstract Syntax Tree) + düzleştirilmiş UI kriterleri üretir.

TEMEL TİPLER (Pydantic v2 discriminated unions):
- SearchIntent: request_id, original_source, language, ontology_version,
  parser_version, model_version, taxonomy_version, constraints: ExpressionNode,
  ui_constraints[], explanations[], ambiguities[], warnings[].
- ExpressionNode: AllOf(children), AnyOf(children), Not(child), Predicate.
- Predicate: field, op, typed_value, unit, modality, provenance, confidence,
  grounding_status, source_span, canonical_value, display_value.
- Typed value örnekleri: DecimalPrice(currency='TRY', amount=3000),
  Size(value='M', system='clothing'), Numeric(value=40, unit='hour').
- Provenance: RULE, ML, USER_CORRECTION, CATALOG_ALIAS, STT_TRANSCRIPT.
- Confidence: numeric model skoru değil, kalibre edilmiş slot güveni veya
  unavailable; UI'a yüzdelik uydurma.
- Ambiguity: conflict_type, candidate_values, question, blocking_flag.
- Source span: UTF-8 byte offset ile karıştırılmayan Unicode codepoint offset;
  orijinal/görüntülenen transcript offset mapping'i tut.

KULLANICI ÖRNEĞİ:
'Sony veya JBL kulaküstü olsun, 6000 altında, beyaz olmasın, ANC şart.'
Kavramsal AST:
AllOf([
  AnyOf([brand = Sony, brand = JBL]),

07D. BASELINE, ÖĞRENEN MODELLER, ANLAM ÇÖZÜMLEME VE EVAL (YENİ)
======================================================================
NLP AŞAMASI GELDİĞİNDE DÖRT ADAYI DENE, VERİ OLMADAN MODEL SEÇME:
M0: Dictionary + regex + finite-state/constraint grammar (kontrol baseline + kalıcı sayı/mantık çekirdeği).
M1: Character n-gram TF-IDF + linear classifier; intent/category/ood için basit ML.
M2: DistilBERTurk fine-tuning birincil üretim adayı (açık uçlu slot span + kategori/OOD;
    BERTurk yalnız çevrimdışı üst-sınır kıyaslaması için). Üretim için ONNX Runtime (INT8/FP16) export.
M3: Kural-kilitli sayı/OR/NOT çekirdeği + DistilBERTurk ONNX span adayları + opsiyonel
    semantic attribute candidate ranking (yalnız kanıtlı faydada).
- 'BERT kullanmak' kalite garantisi değildir. Göreve göre M0 daha güvenilir olabilir.
- Model seçimini test setiyle değil dev setiyle yap. Dev için hiperparametre
  araması sonrası nihai test yalnız rapor aşamasında.
- Label scarcity'de transfer learning, class weighting, sample weighting ve
  stratified sampling; hiperparametre araştırmasını bounded budget ile tut.

ÖNERİLEN EĞİTİM ALTYAPISI (NLP sprintinde dahil edilir):
  Python 3.12; PyTorch, Hugging Face Transformers, Datasets, Evaluate,
  seqeval, scikit-learn, sentence-transformers (semantic opsiyonel).
  GPU erişimi yoksa küçük CPU baseline + küçük model; eğitim GPU üzerinde
  gerekiyorsa açık kaynak/notebook/cloud fiyat ve kişisel veri kontrolü.
  BERTurk adayları:
    https://huggingface.co/dbmdz/bert-base-turkish-cased
    https://huggingface.co/dbmdz/distilbert-base-turkish-cased
  Eğitim yaklaşımı (token classification):
    https://huggingface.co/docs/transformers/en/tasks/token_classification
  Anlamsal eşleştirme adayları:
    https://www.sbert.net/examples/sentence_transformer/applications/semantic-search/README.html
  Modellerin lisans/versiyon/weights güvenliği, inference maliyeti ve
  ticari kullanım şartları model bazında doğrulanmadan üretime alınmaz.

MODEL TASARIMI:
A) Typed numeric parser (HER ZAMAN deterministik): fiyat, birim, numeric product attributes.
B) Slot span extraction: sözlük kuralları + daraltılmış rollü fine-tuned DistilBERTurk (ONNX INT8/FP16)
   ile yalnız sözlüğün kaçırdığı açık uçlu varlık/ürün tipi/özellik adayları.
C) Category/intent inference: rules, cheap linear classifier (M1), or DistilBERTurk ablation.
D) Boolean parser (HER ZAMAN deterministik): NOT/OR/AND/modality lexical dependency + AST
   constraints; salt BIO token classification'a devredilmez, ML rule polarity'sini bozamaz.
E) Semantic alias resolver: 'yağmur geçirmeyen' ~ water resistance candidate;
   exact database attribute seçimi için scored shortlist ve taxonomy gate.
F) OOD detector: düşük güvenli, bilinmeyen kategori ve takip konuşma
   (tek cümlelik ürün araması dışı) durumunda açıklama/soru.
G) Correction loop: kullanıcı kriteri düzeltirse geçici current query için
   düzeltmeyi koru; eğitim feedback'i ayrı izin ve kalite kapısından geçer.

SEMANTIC MATCHING SINIRI:
- Semantic model katalogdaki 'benzer' alanı aday olarak döndürür.
- 'Üzerine su dökülünce bozulmasın' -> suya dayanıklılık adayı olabilir;
  su geçirmezlik sertifikası/kanıtı olmadan kesin olarak çevrilmez.
- Semantic score ve gerçek filter capability iki ayrı değerlendiricidir.
- İlk sürümde ürün içeriği olmadığından review-based quality, sahte yorum,
  'iyi batarya' doğrulaması veya kişiye özel ürün eşleşmesi YAPILAMAZ.
- Çoklu semantik aday top-k <low confidence> ise kullanıcıya seçim sun.

QUALITY GATE HEDEFLERİ (başlangıç, ölçülmüş başarı değil):
  Critical false-positive constraint rate <= %0.5 (özellikle NOT/fiyat).
  Explicit price bound + amount exact >= %98.
  Negative scope exact >= %97 (zorlu, elle incelenmiş ayrı slice).
  OR group exact >= %95 (çoklu marka ve renk alt kümesi).
  Slot entity micro F1 >= %93, macro F1 ayrıca raporlanacak.
  Constraint AST exact match >= %85, zor sorgularda segment raporu.
  OOD/ambiguity detection recall >= %90 (negatif precision ile birlikte).
  Birleşik tek-istekli /search/parse (NLP + bellek-içi ilk LinkResolution, Zero-DB) p95 <= 350ms
  (ONNX INT8/FP16 CPU çıkarım bütçesi ~30-50ms); rule-only M0 p95 <= 200ms;
  kullanıcı kriter düzenlemesi /search/resolve (NLP'siz, Zero-DB) p95 <= 80ms.
  Modelden gelen unsupported bir alana zorunlu filtre uygulanmaz (%100).
  NOT, para ve kimlik gibi yüksek zarar kategorilerinde tek hatalı release-blocker
  regresyon çözülmeden production'a geçilmez.
  NOT: Bu eşikler aspirasyon; veriseti dağılımıyla ve iş riskiyle belgelenecek;
  hiçbir modelin %100 kusursuz olacağı iddia edilmiyor.

W7: Ontology + AST schema + annotation guideline dondur; yanlış iş tanımı üzerinden etiketli veri üretme.
W8: Grup bazlı dataset split + quality audit + gerçek ASR dilimi; etiket kalitesi kötü ise fine-tuning başlatma.
W9: DistilBERTurk/M1 aday deneyleri + model card draft; kaynak/weights lisansı net.
W10: Kural-öncelikli hybrid ablation + calibration + ONNX (INT8/FP16) quantization + GATE-NLP-D.
W11: ONNX shadow/rollback/serving + GATE-NLP-PROD.
W12: 5–8 vitrin kategoride derin Trendyol doğrulaması + TrendyolRouteStrategy sertleştirmesi.

MODELÜ ÜRETİME ALMA KARAR AĞACI:
- Rules kritikleri doğru, ML başarısız -> rules release, ML research backlog.
- ML başarıyı artırıyor ama p95 yavaş -> offline optimize/quantize veya gated use.
- ML yanlış kritik alanlar üretiyor -> reject/abstain, sadece rules trusted.
- ML net fayda sağlıyor ve tüm güvenlik/latency/eval koşulları sağlanıyor -> hybrid.
- Provider mapping zayıf -> NLP başarılı olsa bile mağaza filtresi iddiası YOK;
  HEH ürünü 'akıllı arama ifadesi oluşturucu' olarak şeffaf konumlandırılır.

ÇALIŞMANIN AI ENGINEER PORTFÖY DEĞERİ:
1. Türkçe alışveriş sorgularına özgü problem formülasyonu ve ontology.
2. Benchmark / golden set / annotation handbook / leakage kontrolü.
3. Deterministik baseline ve fine-tuned transformer karşılaştırması.
4. Complex boolean constraint graph + negation scope çözümleme.
5. Confidence calibration, abstention ve insan onayı.

08. TRENDYOL ADAPTÖRÜ, URL SÖZLEŞMESİ VE KANIT ZİNCİRİ
======================================================================
Trendyol'un satıcı Marketplace API'si, her ürünü tüketici gibi aramaya yönelik açık API
olarak kabul EDİLEMEZ. Arama URL'lerindeki gayriresmî parametreler değişebilir.

KAPSAM STRATEJİSİ — DAR VE DERİN (5-8 VİTRİN KATEGORİ) + DÜRÜST UZUN KUYRUK:
- Vitrin Kategoriler (5-8 yüksek frekanslı dikey: Mont/Üst Giyim, Ayakkabı, Kulaklık,
  Laptop, Akıllı Telefon, Çanta/Aksesuar vb.): Marka, renk, beden, fiyat ve seçili temel
  özelliklerde gerçek web/mobil kanıtına bağlı tam FILTER_VERIFIED desteği ve haftalık
  regresyon kontrolü.
- Uzun Kuyruk Kategoriler (diğer tüm kategoriler): Tek geliştiricinin tüm kategorilerdeki
  binlerce facet ID'sini elle doğrulaması ölçeklenmez; bu nedenle doğrulanmamış kategori-özel
  facet ID'si asla uydurulmaz. Bu kategorilerde dürüstçe doğrulanmış genel fiyat aralığı
  (prc -> FILTER_VERIFIED) + akıllı arama metni (q -> QUERY_ONLY) + açık UNSUPPORTED
  raporlama moduna düşülür.

TRENDYOL ROTA STRATEJİSİ (TrendyolRouteStrategy) VE ZERO-DB SNAPSHOT:
- Trendyol birçok kategoride yalnız ?key=val değil, kategoriye özgü SEO slug'ları ve
  -x-g...-c...-b...-a... şeklinde birleşik facet path kodları kullanır. URLBuilder bunu
  iki açık stratejiyle soyutlar:
    1) VerifiedFacetPathStrategy: Kanıtlanmış SEO slug + -x- facet segmentleri (yalnız vitrin kategoriler).
    2) CanonicalSearchQueryStrategy: Kanıtlı /sr?q=...&prc=... parametreleri (genel/uzun kuyruk fallback).
- Kanıtlanmamış bir -x- segmenti asla sentezlenmez; yalnız registry'de doğrulanan kalıp üretilir.
- Runtime eşleme sözlüğü PostgreSQL'den değil, imzalı/versiyonlu repo JSON'undan yüklenen
  bellek-içi salt-okunur (in-memory immutable) snapshot'tan okunur (0 ms DB maliyeti).

LinkResolution modeli:
  input: CanonicalCriteria + category_context + mapping_version
  output:
    provider = 'trendyol'
    https_url = 'https://www.trendyol.com/...' [yalnız izinli host]
    applied_filters[] = her biri parametre ve doğrulama referansıyla
    query_only[] = metin olarak arananlar
    unsupported[] = uygulanamayanlar, gerekçe, kullanıcıya öneri
    warning_level = none|partial|critical
    verified_at, mapping_version

Üç durumun teknik adları:
  FILTER_VERIFIED    : gerçek site/uygulama testinde ilgili filtre seçilmiş.
  QUERY_ONLY         : q metni olarak gidiyor; kesin filtre iddiası yok.
  UNSUPPORTED        : negatif / belirsiz / olmayan filtre, sessiz kabul yok.
  UNKNOWN            : ürün sayfası/URL davranışı doğrulanmadı, 'verified' sayılmaz.

Bir filtre eşlemesini aktive etme şartları:
- En az bir gerçek web ve bir gerçek mobil geçiş testi (mümkünse farklı oturum).
- Parametre + test tarihi + kategori + test sonucu + ekran kanıtı + tester notu.
- Çoklu değer kombinasyon testi: aynı alan OR, başka alanla AND, min/max.
- Kategori değiştirme sonrası parametrenin hâlâ semantiği koruduğu kontrol.
- Regresyon başarısızsa mapping status = disabled/UNKNOWN; yeni linklerde kullanılmaz.

Yapılandırma örnek kaydı:
{
  "provider":"trendyol", "category":"headphones", "field":"brand",
  "value":"Sony", "param":"<VERIFIED_PARAM>", "param_value":"<VERIFIED_ID>",
  "status":"UNVERIFIED", "tested_at":null, "evidence":null,
  "notes":"Bu satır örnek; gerçek marka ID'si veya URL doğrulaması değildir."
}

GÜVENLİ URL İNŞASI:
- Bilinmeyen parametre uydurma; yalnız allowlist'teki anahtarları kabul et.
- Değerleri URL encode et, string concatenation ile enjeksiyon yapma.
- https + allowlisted hostname, host normalizasyonu, boş kullanıcı yönlendirmesi yok.
- Open redirect engelle: istemciden keyfî redirect URL kabul etme.
- Haricî mağazaya çıkış kullanıcı eylemiyle; deep link desteklenmezse web aç.
- Parametreleri kategori bazında güvenli sırayla kur; uygulama/WEB davranış farkını raporla.
- q'da marka adını görmek, marka filtresinin uygulanmasıyla karıştırılmaz.
- 'haricî marka hariç' gibi NOT filtre uygulanmıyorsa ürünü garanti etme.
- Filtre parametrelerini güncellemek için sunucuda versioned release + geri alma mekanizması.

09. API TASARIMI: TEK KAYNAK, TİPLİ SÖZLEŞME
======================================================================
Temel prefix: /api/v1 | JSON, UTC tarih, UTF-8, HTTPS.
OpenAPI, FastAPI Pydantic şemalarından üretilir; TypeScript istemci otomatik üretilir.

GET  /api/v1/health/live         -> 200 {"status":"ok"}; DB ve dış bağımlılıktan bağımsız liveness.
GET  /api/v1/health/ready        -> 200/503 bellek-içi mapping_snapshot + nlp_adapter hazır mı
                                    (db_status alanı ayrı raporlanır; DB kesintisi çekirdek aramayı kapatmaz).
POST /api/v1/search/parse        -> tek ağ isteğinde (1-RTT) SearchIntent AST + ui_constraints
                                    + warnings + İLK LinkResolution önizlemesini döner (Zero-DB).
POST /api/v1/search/resolve      -> yalnız kullanıcı UI'da kriter düzenlediğinde (USER_CORRECTION)
                                    NLP koşturmadan güncel AST -> LinkResolution hesaplar (Zero-DB).
GET  /api/v1/search/capabilities -> kategori/alan/vitrin kapsamı + sürüm (in-memory snapshot, Zero-DB).
GET  /api/v1/me                  -> hesap açıkken profil.
GET  /api/v1/history             -> sadece giriş yapmış kullanıcı.
POST /api/v1/history             -> giriş yapmış, açıkça kaydetmek isteyen kullanıcı.
DELETE /api/v1/history/{id}      -> yalnız sahibine ait kayıt.
DELETE /api/v1/history           -> sahibinin tüm geçmişini sil.
DELETE /api/v1/me                -> kullanıcının silme iş akışını tetikle.

10. POSTGRESQL VERİ MODELİ, GÖÇLER VE SAKLAMA
======================================================================
Veritabanı yalnız hesap, açık rızalı bulut geçmişi, silme orkestrasyonu ve çevrimdışı
yönetim kayıtlarını tutar. Misafir arama ve filtre çözme hattı %100 bellek-içi immutable
snapshot üzerinde çalışır (Zero-DB Hot Path); her aramada sunucuya profil veya sorgu yazılmaz.

TABLO: users
  id (uuid pk), auth_provider_sub (text unique not null), created_at,
  updated_at, deletion_requested_at nullable, deleted_at nullable.
  Email gibi doğrudan PII asgari; yönetilen identity provider'da tutulması tercih.

TABLO: saved_searches
  id (uuid pk), user_id (fk users, index), query_text (text, length check),
  canonical_criteria (jsonb; schema_version), parser_version,
  created_at, updated_at.
  İlgili kullanıcı için sorgu limiti; silme işleminde cascade/anlaşılır politika.

TABLO: user_preferences
  user_id (pk/fk), history_sync_enabled (boolean), locale,
  theme_preference, created_at, updated_at.
  Hassas sağlık/kişisel özellikleri otomatik profilleme yok.

TABLO: filter_mapping_releases
  id, provider, category_key, version, status (draft/verified/disabled),
  activated_at, created_at, notes.

TABLO: filter_mapping_entries
  id, release_id (fk), field, operator, canonical_value,
  url_parameter, url_value, verification_status, verified_at,
  evidence_reference, test_platform, expires_at nullable.
  URL parametre kimlikleri gözlem/test kanıtıyla izlenir; minik katalogda
  sürümlü repo JSON + DB'deki etkin sürüm metadata'sı da alternatif.
  İlk fazda ve runtime arama hot path'inde tek yetkili kaynak = versiyonlu repo JSON'undan
  boot'ta yüklenen bellek-içi immutable snapshot; runtime /search/* isteklerinde DB tablolarına
  SQL sorgusu atılmaz (DB tabloları yalnızca yönetim/denetim ve çevrimdışı kanıt indeksi içindir).

TABLO: privacy_deletion_requests
  id, user_id, requested_at, completed_at, status, error_code nullable.
  PII minimizasyonu; işlemi kontrol edilebilir kılar; hukukî saklama ayrı danışılır.

TABLO: redirect_events (opsiyonel, analitik etkinse)
  id, timestamp_bucket, platform, outcome, mapping_version,
  category_bucket; query_text, URL'nin tamamı veya kullanıcı kimliği YOK.
  Ticari satış/komisyon değil sadece kullanıcı eylemi sayısıdır.

INDEX / MIGRATION:
- saved_searches(user_id, created_at DESC); kapsamlı arama yoksa GIN gereksiz.
- Bütün DB değişiklikleri Alembic migration ve downgrade stratejisiyle.
- Bir schema sürümü hem eski hem yeni API dağıtımıyla uyumlu olacak şekilde rollout.
- Expand -> deploy -> backfill -> contract; üretimde yıkıcı migration tek adımda yok.
- Yerel geliştirmede PostgreSQL Docker Compose; CI testlerinde ayrı temiz DB.
- Staging ve production credentials, DB ve yedekler fiziksel/mantıksal ayrılmalı.
- Üretim erişimi minimum yetkili DB rolü; admin rolü runtime'da kullanılmaz.

LOCAL STORAGE:
- Anonim geçmiş uygulamanın kendi SQLite DB'sinde.
- Gereksiz PII saklama yok; kullanıcının manuel silmesi + kayıt kapatma.
- Hesap açınca geçmişi buluta taşıma otomatik değil; açık seçimle.

YEDEKLEME / KURTARMA:

11. KİMLİK, HESAP VE YETKİLENDİRME

V1 hesap akışı:

- Token expiry/refresh işleyişi ve offline hata kullanıcıya anlaşılır.
- Sign in with Apple şartlarını tetikleyen üçüncü taraf sosyal girişler eklenirse
  Apple politikası kontrolü zorunlu; mümkünse ilk sürümde sosyal giriş ekleme.

GUEST -> AUTH MIGRATION:
- 'Yerel geçmişi hesabına ekle?' onayı; default hayır.
- UUID'lerle deterministik kayıt deduplication; birleşimde kullanıcı onayı.
- Başarısız senkronizasyon yerel geçmişi silmez.
- Çok cihazda sıralama UTC timestamp ile.

DELETE ACCOUNT:
- Uygulamadan gerçek silme akışı; iki adımlı onay + gerekiyorsa kimlik yeniden doğrulama.
- FastAPI kendi DB ve sağlayıcı tarafında silme orkestrasyonu; iş hata alırsa
  durum 'pending/retry' olarak izlenir, kullanıcıya yanlış 'silindi' mesajı verilmez.
- Google Play için uygulama içi ve web üzerinden silme talep yolu hazırlanır.
- Apple App Store için uygulama içi hesap silme seçeneği test edilir.
- E-posta tokenı/arama geçmişi/kimlik atıfları ve log-retention envanteri tamamlanmadan
  store release yapılmaz.

12. GÜVENLİK, GİZLİLİK, KVKK VE YASAL KONTROL
======================================================================
VARLIK ENVANTERİ:
- Ses verisi (geçici, mikrofondan STT sağlayıcısına; saklanmaz varsayımı).
- STT metni (kullanıcının girdisi; server parse için gönderilir).
- Arama geçmişi (yerel; senkronize edilirse kullanıcı hesabına bağlı sunucuda).
- Giriş kimliği ve token (yönetilen sağlayıcı + SecureStore).
- Teknik olay logları (request_id, latency, hata kodları; ham arama yok).

Tehdit modeli (STRIDE odaklı):
T-01 Token çalınması -> SecureStore, kısa ömür, TLS, revocation.
T-02 Başkasının geçmişini okuma (IDOR) -> server-side user binding + ownership tests.
T-03 URL üzerinden open redirect -> sadece allowlisted Trendyol host + HTTPS.
T-04 Başka host'a parametre enjeksiyonu -> kontrollü URL builder, encoding.
T-05 Public parse API'ye bot yükü -> request size sınırı, edge rate limit, input timeout.
T-06 Yanlış filtre ile yanıltma -> evidence/status + manuel kontrol + reg. test.
T-07 Dependency/GitHub Actions zinciri -> lockfile, secret scanning, pinned actions.
T-08 CI secret sızıntısı -> PR ortamına prod secret verilmez, environment protection.
T-09 Hesap silme eksikliği -> end-to-end deletion runbook/test.
T-10 Analytics PII sızıntısı -> SDK redaction, sampling, URL/query redaction.
T-11 Ses arka planda kalması -> app lifecycle stop, explicit consent, resource cleanup.
T-12 Sahte uygulama/marka ortaklığı algısı -> açık ürün dili, resmî ilişki iddiası yok.

BACKEND GÜVENLİK TEMELİ:
- HTTPS TLS, HSTS web domain için; şifreler .env.example'da boş açıklama olarak.
- DB sorguları parametrik SQLAlchemy; raw SQL zorunluysa bind params.
- Pydantic strict field validation; max body size, timeout, unicode sanitation.
- Structured JSON logs; trace_id ve request_id; e-posta/token/query değerini maskeler.
- CI'da SAST/dependency check, temel secret scan; prod imajında non-root user.
- GitHub Actions GITHUB_TOKEN en düşük yetki; third-party actions tam SHA pin.
- Servis yönetim endpoint'leri internetten serbest erişime açık değil.
- Abuse için IP başına sadece statik sınır değil, proxy trusted headers kontrolü.
- Auth kullanıcılarının kendi verileri dışında kayıt oluşturması/silmesi engellenir.
- CORS mobil istemci güvenlik sınırı değildir; web panel gelirse origin whitelist.
- Sırlar release dosyalarında, uygulama bundle'ında, screenshotlarda görünmez.
